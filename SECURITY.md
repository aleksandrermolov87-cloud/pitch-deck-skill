# Безопасность

## Как сообщить об уязвимости

Не открывайте публичный issue. Используйте приватный отчёт: вкладка **Security → Report a vulnerability** в этом репозитории. Ответ — в течение нескольких рабочих дней.

## Поддерживаемые версии

Исправления выходят в последнем релизе (`vX.Y.Z`). Обновление — `zsh scripts/update.sh`.

## Как устроена защита

- Устанавливайте и обновляйте только релизы-теги, не ветку `main`. Теги подписаны SSH-ключом автора; `update.sh` проверяет подпись по `.github/allowed_signers` из уже установленной версии и показывает изменения в скриптах и инструкциях агента до переключения. Так же обновляется установка без `.git`: `allowed_signers` из нового релиза для проверки не используется, `setup.sh` релиза запускается только после проверки подписи и в промежуточной папке, прежняя версия остаётся резервной копией (`update.sh --rollback`). `PDS_REMOTE` меняет только адрес, откуда скачивается релиз, а подпись проверяется тем же ключом. Переменная нужна только для тестов.
- Изменения в `scripts/`, `templates/`, `SKILL.md`, `reference/` проходят ревью владельца (`CODEOWNERS`); принудительный пуш и удаление `main` запрещены.
- Проверка на утечки — pre-commit (`scripts/hooks/pre-commit`) и CI (`.github/workflows/check.yml`); на GitHub включены secret scanning и push protection.
- Зависимости закреплены (`requirements.txt` вместе с транзитивными, `package-lock.json`), npm-пакеты ставятся без install-скриптов, pip в venv поднимается до исправленной версии.
- Известные уязвимости проверяет `scripts/deps_audit.sh` (`npm audit` и `pip-audit` по venv вместе с pip): без него `release.sh` не выпускает версию. В CI то же делает задача `deps`, Dependabot раз в неделю предлагает обновления npm, pip и GitHub Actions. Actions закреплены по SHA.
- Агент читает внешний контент как данные и не выполняет из него инструкции; необратимые действия — только с подтверждения пользователя (`SKILL.md`, раздел «Безопасность»).
- Ключи API не хранятся в скилле: пользователь вводит их сам в настройках Claude Code.
