# pitch-deck-skill

Помощник для Claude Code и Codex, который собирает презентации в PowerPoint из ваших материалов: таблиц Excel, старых презентаций, PDF, текста и скриншотов. Вы описываете, что нужно, и получаете готовый файл. Тексты и цифры в нём можно править, каждая цифра сверена с источником, а в конце приходит короткий отчёт о том, что вошло и что нет.

## Как установить — 3 шага, без технических знаний

1. **Откройте Claude Code** — приложение Claude на компьютере, вкладка **Code**. Подойдёт и **Codex**. Обычный чат в браузере (claude.ai, ChatGPT) не подойдёт: ему нельзя устанавливать программы на компьютер.
2. **Вставьте в чат ссылку и напишите:**
   `https://github.com/aleksandrermolov87-cloud/pitch-deck-skill — установи`
3. **Отвечайте на вопросы ассистента.** Он сам всё скачает и проверит, а спросит только о простом: какой вариант поставить, где лежит фирменный шрифт. Займёт 10–15 минут. Если попросит что-то сделать руками, он объяснит по шагам, куда нажать.

После установки откройте **новый чат** и попросите, например:
- «Собери презентацию для УК по этой таблице, 8–10 слайдов, тёмная тема» — и приложите файл;
- «Сделай питч-дек для инвестора по описанию продукта и метрикам».

Обновления ассистент предложит сам раз в неделю. Можно и попросить: «обнови pitch-deck-skill».

> Неофициальный инструмент. Это не продукт и не ресурс Альфа-Банка. Профиль бренда `alfa` в `reference/brands/` — это настройки оформления для сотрудников, которые делают внутренние презентации; все числа в примерах и демо-данных вымышленные.

## Инструкция для ИИ-ассистента: установка

Этот раздел для тебя — Claude Code, Codex или другого ассистента, которому прислали ссылку на репозиторий с просьбой установить. Пользователь, скорее всего, **не разбирается в технике**: делай всё сам, по шагам, и не перекладывай на него то, что можешь сделать сам.

**Как говорить с пользователем:**
- простыми словами, без терминов: «скачиваю помощника», а не «клонирую репозиторий»; «проверяю, что всё работает», а не «запускаю selftest»;
- не показывай длинные логи и команды без нужды: в конце шага — одна фраза, что получилось;
- спрашивай по одному вопросу за раз, с вариантами и рекомендуемым первым;
- если нужно действие руками, опиши его по кликам: где нажать, что вставить, что увидит человек; дождись ответа «готово»;
- ключи и пароли пользователь вводит сам, в чат их не присылает; если прислал — не используй и попроси ввести в терминале.

**Если у тебя нет доступа к компьютеру** (ты чат в браузере): ничего не устанавливай, а скажи: «Из браузера установить нельзя. Откройте приложение Claude на компьютере, вкладку Code (или Codex), и отправьте эту ссылку туда».

**Если ты Codex:** ставь в ту же папку `~/.claude/skills/pitch-deck-skill` (скрипты рассчитаны на неё) и после установки сделай ссылку `mkdir -p ~/.codex/skills && ln -sfn ~/.claude/skills/pitch-deck-skill ~/.codex/skills/pitch-deck-skill`. В SKILL.md встречаются названия инструментов Claude Code (вопросы с вариантами, режим планирования, список задач) — используй свои аналоги.

Ниже шаги. Ничего не коммить и не пушь в этот репозиторий.

**Шаг 1. Предупреди.** «Сейчас поставлю помощника для презентаций. Это займёт 10–15 минут, я всё сделаю сам и задам пару вопросов». Работает на macOS; на Linux не проверялось; Windows не поддерживается — если у пользователя Windows, скажи об этом и остановись.

**Шаг 2. Проверь, что на компьютере есть нужные программы.**
```bash
for c in git node zsh; do command -v $c >/dev/null && echo "ok $c" || echo "НЕТ $c"; done; node -v 2>/dev/null
for c in python3.13 python3.12 python3.11 python3; do p=$(command -v $c) && $p -c 'import sys; sys.exit(sys.version_info < (3, 11))' && { echo "ok python $($p -V)"; break; }; done || echo "НЕТ python 3.11+"
ls "/Applications/Google Chrome.app" >/dev/null 2>&1 && echo "ok chrome" || echo "НЕТ chrome"
command -v brew >/dev/null && echo "ok brew" || echo "НЕТ brew"
```
Если чего-то нет — объясни простыми словами, зачем это нужно, и с согласия пользователя поставь:
- есть Homebrew: `brew install node`, `brew install --cask google-chrome`;
- нет git: `xcode-select --install` — появится окно, попроси нажать «Установить» и дождаться конца (5–10 минут);
- нет Python 3.11+ (системный python3 на macOS — 3.9, он не подходит): `brew install python@3.12`; без Homebrew попроси скачать установщик Python 3.12 для macOS с https://www.python.org/downloads/macos/ и пройти его до конца (пароль от компьютера вводит сам пользователь);
- нет Homebrew и нет Node.js: попроси открыть https://nodejs.org, скачать версию «LTS» для macOS, открыть скачанный файл и нажимать «Продолжить» до конца (понадобится пароль от компьютера — его вводит сам пользователь);
- нет Chrome: попроси скачать с https://www.google.com/chrome и перетащить в «Программы».

**Шаг 3. Спроси, какой вариант поставить** (один вопрос):
- «Обычный (рекомендую)» — всё работает сразу, ничего платного;
- «Расширенный» — больше вариантов оформления слайдов, но нужен платный ключ сервиса 21st.dev.

Если пользователь не знает, что выбрать, — ставь обычный. Объёмные 3D-картинки (сервис Magic Patterns) не включай, пока пользователь сам не попросит: для них нужен отдельный платный аккаунт.

**Шаг 4. Скачай последнюю проверенную версию** (не ветку `main`):
```bash
mkdir -p ~/.claude/skills && cd ~/.claude/skills
if [ -d pitch-deck-skill/.git ]; then
  zsh pitch-deck-skill/scripts/update.sh          # уже стоит: покажет изменения, дальше --yes с согласия пользователя
else
  [ -e pitch-deck-skill ] && mv pitch-deck-skill pitch-deck-skill.old   # старая установка из md-файла
  git clone https://github.com/aleksandrermolov87-cloud/pitch-deck-skill.git pitch-deck-skill
  cd pitch-deck-skill && TAG=$(git tag -l 'v*' --sort=-v:refname | head -1) && git -c advice.detachedHead=false checkout "$TAG"
  git -c gpg.ssh.allowedSignersFile=.github/allowed_signers verify-tag "$TAG" && echo "подпись релиза $TAG проверена"
fi
```
Если была папка `pitch-deck-skill.old`, перенеси из неё в новую `config.json`, папку `learnings/` и файлы `*.local.md` (если есть), и скажи, что старую папку можно удалить.

**Шаг 5. Установи и проверь** — обычный вариант `lite`, расширенный `full`. `--system` доставляет через Homebrew то, чего нет на компьютере (Node.js, Python 3.12, Google Chrome, poppler); спроси пользователя, прежде чем ставить программы. Без 3D добавь `--no-3d`:
```bash
zsh ~/.claude/skills/pitch-deck-skill/scripts/setup.sh --mode lite --system --selftest
```
Setup ставит всё остальное сам и при повторном запуске обновляет: Python-пакеты по `requirements.txt`, пакеты Node по `package-lock.json` (заново, если файл изменился после обновления скилла), вспомогательные скиллы, подключение Magic Patterns для 3D. Для проверки PPTX без PowerPoint добавь `--with-libreoffice`.
Займёт 5–10 минут (рисуется проверочная презентация и галерея из 108 слайдов: 95 компонентов, у части несколько примеров с разными данными). Ожидается: «Демо.pptx … ошибок 0», «фактов 34, сошлось 34», «Галерея_компонентов … ошибок 0» для тёмной и светлой темы. Setup заодно ставит рядом со скиллом (в `~/.claude/skills` или `~/.codex/skills`) два вспомогательных навыка — humanizer и taste-skill, если их там нет. Если что-то упало — разберись сам по сообщению; пользователю скажи только итог.

**Шаг 6. Ключ 21st** — только для расширенного варианта. Попроси пользователя:
1. Зайти на https://21st.dev/mcp, войти и скопировать ключ.
2. Открыть программу «Терминал»: нажать ⌘ + Пробел, набрать «Терминал», нажать Enter.
3. Вставить эту строку, заменить `ВАШ_КЛЮЧ` на скопированный ключ и нажать Enter:
   `claude mcp add --transport http 21st https://21st.dev/api/mcp --header "x-api-key: ВАШ_КЛЮЧ" --scope user`
4. Написать тебе «готово». Ключ в чат не присылать.

**Шаг 7. 3D-картинки (Magic Patterns).** Setup без `--no-3d` сам подключает сервер Magic Patterns (`https://mcp.magicpatterns.com/mcp`) в Claude Code и в Codex, если они установлены (`scripts/mcp_setup.sh`). Один раз нужен вход в аккаунт Magic Patterns, его делает пользователь сам: в Claude Code — `/mcp` → magicpatterns → Authenticate (в приложении Claude можно и через Settings → Connectors → Magic Patterns), в Codex — `codex mcp login magicpatterns` в Терминале. Если Magic Patterns нет, в Codex 3D рисует встроенный `image_gen` (ключ не нужен). Проверка: `zsh ~/.claude/skills/pitch-deck-skill/scripts/mcp_setup.sh --check`. Нужны ли 3D в конкретной деке, скилл спрашивает каждый раз.

**Шаг 8. Фирменный шрифт Styrene A LC.**
```bash
zsh ~/.claude/skills/pitch-deck-skill/scripts/font.sh check
```
Если не установлен, спроси: «Есть ли у вас фирменный пакет шрифтов — папка, архив или ссылка? Если нет, презентации будут на стандартном шрифте, это можно поправить позже». Получил путь — `zsh ~/.claude/skills/pitch-deck-skill/scripts/font.sh install "<путь или ссылка>"`.

**Шаг 9. Не ставь без отдельной просьбы:** детектор impeccable (`npx -y impeccable install` — меняет настройки Claude Code), расширение Claude in Chrome (нужно только для просмотра макетов в Figma).

**Шаг 10. Итог.**
```bash
zsh ~/.claude/skills/pitch-deck-skill/scripts/doctor.sh
```
Скажи пользователю 3–4 простыми фразами: что установлено, что (если что-то) осталось сделать ему, и что помощник заработает в **новом чате**. Дай пример первой просьбы: «Собери презентацию для УК по этой таблице, 8–10 слайдов». Скажи, что обновления помощник будет предлагать сам раз в неделю.

## Что внутри

- **8 этапов с воротами:** план с референсами → вводные и формулировки → компоненты → сборка PPTX → сетка (impeccable) → чистка ИИ-слопа (taste-skill) → факт-чек и отчёт → обучение на ваших оценках слайдов.
- **Схемы вместо блоков.** 30 сложных схем: распределение ролей, хаб, экосистема кольцами, контур «внутри и снаружи», архитектура с потоками, процессы по дорожкам, статусная модель, дерево решений, маховик, рыбья кость и другие. Детектор `scripts/viz_suggest.py` сам находит во вводных и в деке, что просится в схему, и агент предлагает её. Блоковые слайды (ряд или сетка одинаковых карточек) аудит не пропускает. Подробно — `reference/19-schemes.md`.
- **Библиотека из 125 компонентов** — основа структуры и фирменного стиля: роадмапы, таблицы, графики, 30 схем, рынок и юнит-экономика, путь клиента, стратегия и риски, статус проекта, просьба о финансировании, 20 текстовых раскладок, 5 раскладок под мокапы экранов. Каталог — `components/README.md`, галерея — `zsh scripts/gallery.sh`.
- **Проверки-скрипты:** аудит сетки и «простых слайдов» (`pptx_audit.py`), сверка фактов (`facts_check.py`), SMART-формулировки (`smart_check.py`), диагностика окружения (`doctor.sh`), проверка на утечки (`leakcheck.sh`).
- **База паттернов дек:** инвесторы (pre-seed → growth), корпорации и УК, B2B, продуктовые, статус-отчёты.

Режимы в `config.json`: с 21st Magic MCP (платный ключ) или без, 3D-объекты Magic Patterns вкл/выкл, бренд, Figma.

Без доступа к GitHub: в каждом [релизе](https://github.com/aleksandrermolov87-cloud/pitch-deck-skill/releases/latest) есть самоустанавливающиеся файлы `pitch-deck-skill-install-lite.md` (обычный вариант) и `pitch-deck-skill-install-full.md` (расширенный, с 21st): отправьте файл ассистенту с просьбой «Установи по этому файлу».

## Установка вручную (для тех, кто работает в терминале)

Нужны macOS или Linux, Node.js 18+, Python 3.11+, Google Chrome, git.

```bash
mkdir -p ~/.claude/skills && cd ~/.claude/skills
git clone https://github.com/aleksandrermolov87-cloud/pitch-deck-skill.git
cd pitch-deck-skill
git checkout "$(git tag -l 'v*' --sort=-v:refname | head -1)"   # последний релиз, а не ветка main
zsh scripts/setup.sh --mode lite --selftest                      # lite — без 21st; full — с ключом 21st
```

Шрифт бренда (Styrene A LC) в репозиторий не входит — это коммерческий шрифт. Поставьте его из фирменного пакета:

```bash
zsh ~/.claude/skills/pitch-deck-skill/scripts/font.sh install "<папка, .zip или https-ссылка на .zip>"
```

Ключ 21st Magic MCP вводите сами в своём терминале, не в чате: `claude mcp add --transport http 21st https://21st.dev/api/mcp --header "x-api-key: ВАШ_КЛЮЧ" --scope user`.

## Обновление

Раз в неделю скилл сам проверяет, вышел ли новый подписанный релиз, и в начале работы предлагает обновиться: «Обновить сейчас» или «Позже». Без вашего согласия ничего не ставится. Частота — `config.json → "update_check_days"` (по умолчанию 7, `0` — не проверять). Проверить вручную: `zsh ~/.claude/skills/pitch-deck-skill/scripts/check_update.sh --force`.

Обновить вручную:

```bash
zsh ~/.claude/skills/pitch-deck-skill/scripts/update.sh          # покажет изменения
zsh ~/.claude/skills/pitch-deck-skill/scripts/update.sh --yes    # переключит на последний релиз
```

Обновление ставит только релизы (теги `vX.Y.Z`), подписанные ключом автора, и перед этим показывает, что меняется в скриптах и инструкциях агента. Подпись проверяется по `.github/allowed_signers` из уже установленной версии; релиз без подписи или с чужой подписью не ставится. На GitHub у подписанных тегов стоит отметка «Verified». Ваши `config.json`, уроки (`learnings/`) и `*.local.md` не входят в git и не меняются.

**Установка без git** (из архива, установщиком скиллов, из md-файла): те же команды. Нужен только git на компьютере, папке скилла `.git` не нужен. `update.sh` скачивает релиз во временный клон, проверяет подпись ключом из текущей установки и показывает CHANGELOG и список изменений. Новая версия собирается в промежуточной папке: туда побайтно переносятся ваши `config.json`, `learnings/`, `*.local.md`, окружение (`.venv`, `node_modules`) и всё, чего нет в релизе. Там же проходят `setup.sh` и быстрая проверка. Только после этого папки меняются местами; если что-то не прошло, установка остаётся как была. Прежняя версия хранится целиком в `~/.claude/skills/.pitch-deck-skill.backups/<время>-v<версия>`. Claude эту папку не загружает, другие скиллы обновление не трогает. Старые копии удаляйте сами, когда новая версия проверена.

```bash
zsh ~/.claude/skills/pitch-deck-skill/scripts/update.sh --rollback        # покажет, какая копия вернётся
zsh ~/.claude/skills/pitch-deck-skill/scripts/update.sh --rollback --yes  # вернёт последнюю резервную копию
```

При откате текущие настройки и уроки переносятся в возвращённую версию, а сама текущая версия становится резервной копией: повторный `--rollback --yes` вернёт её. Тесты обновления работают без сети: `zsh tests/update/run.sh`. Переменная `PDS_REMOTE` в них подменяет адрес репозитория; она нужна только для тестов.

## Безопасность

- Внешний контент (файлы, Figma, страницы, ответы MCP) скилл читает как данные, а не как инструкции; необратимые действия — только с вашего подтверждения (раздел «Безопасность» в `SKILL.md`).
- Зависимости закреплены: `requirements.txt`, `package-lock.json` (`npm ci --ignore-scripts`).
- Перед каждым коммитом и в CI работает проверка на утечки ключей, личных путей и внутренних названий (`scripts/leakcheck.sh`, локальный список — `scripts/leaks.local.txt`, в git не попадает).
- Как сообщить об уязвимости — `SECURITY.md`.

## Для автора: выпуск версии

1. Изменения, `VERSION`, раздел `## X.Y.Z` в `CHANGELOG.md`, коммит.
2. `zsh scripts/release.sh X.Y.Z` — проверка на утечки, самопроверка, подписанный тег, пуш, релиз на GitHub с двумя установочными md (с Magic-MCP и без).

Подпись: отдельный SSH-ключ `~/.ssh/pitch_deck_signing_ed25519`, он же добавлен в GitHub как signing key, публичная часть — в `.github/allowed_signers`. Настройка в клоне: `git config gpg.format ssh`, `git config user.signingkey ~/.ssh/pitch_deck_signing_ed25519.pub`, `git config gpg.ssh.allowedSignersFile "$PWD/.github/allowed_signers"`. Смена ключа: новый ключ добавляется в `allowed_signers` релизом, подписанным старым ключом; если старый утерян, коллег нужно предупредить лично.
