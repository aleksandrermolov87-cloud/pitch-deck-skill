# Роадмапы и таблицы: подбор компонента под вопрос

Компоненты найдены в 21st Magic MCP 26.10.2026 и просмотрены глазами (id для `mcp__21st__get_component`).
Из них берётся **структура**, а не вёрстка: цвет и шрифт всегда из `theme.json`, рамки и карточки убираются
по `reference/10-beyond-blocks.md`.

## Роадмап: какой вопрос он отвечает

Все виды ниже уже собраны в библиотеке компонентов (`components/README.md`): `timelineAxis`, `ganttLanes`, `nowNextLater`, `quarterHorizon`, `tableEditorial`, `heatmap`, `comparison`. Компонент 21st нужен, только если библиотечный не отвечает на вопрос слайда.

| Вопрос зрителя | Вид | Компонент-источник | Как собрать без блоков |
|----------------|-----|--------------------|------------------------|
| «Что и когда выходит?» (даты известны) | **открытая ось с вехами** | Release Cycle Timeline `29956`, Timeline (slide-cn) `28298` | линия на всю ширину, узлы-кольца на датах, пройденный участок закрашен акцентом, текст **под** узлом: дата мелко, результат жирно, 1 строка пояснения |
| «Кто что делает параллельно?» | **гант по дорожкам** | Gantt Chart `38523`, Gantt `632` | дорожки сгруппированы по направлениям (подпись группы капителью слева), полосы фаз, **маркер «сегодня»** вертикальной акцентной линией, вехи ромбами, зависимости тонкими стрелками |
| «Что сейчас, что следом, что потом?» (даты не обещаем) | **Now / Next / Later** | Roadmap Board `28420` (взять только структуру, без карточек) | 3 типографические колонки, плотность падает: «Сейчас» с деталями, «Следом» с названиями, «Потом» темами; колонки разделены воздухом |
| «Куда идём за 2–3 года?» | **горизонт по кварталам** | эталон `roadmap-quarters` (`learnings/gallery/good/`) | строки-направления по годам, отметки кварталов, пунктир «без срока» |
| «Как растут деньги вместе с релизами?» | **ось релизов + столбики** | эталон `timeline-months` | ось с вехами сверху, столбики результата снизу на той же шкале месяцев |

Общие правила роадмапа:
- **Покажи, где мы сейчас:** маркер «сегодня» или закрашенная часть оси. Без него роадмап не читается.
- **Детализация по аудитории:** для руководства горизонты и темы, для команды даты и задачи. Чем больше деталей, тем сильнее ожидание, что план не изменится.
- **Подпись вехи — результат, а не работа:** «ДМС продаётся в НИБ», а не «Разработка ДМС».
- **Не больше 10–12 подписей** на основном слайде, остальное в приложение.
- **Близкие вехи группируются в кластер:** одна скобка на оси от первой до последней вехи, одна выноска, подписи столбиком. Отдельные выноски у соседних месяцев перечёркивают подписи (`pptx_audit.py`: «линия перечёркивает текст»).
- **Пункты роадмапа пишутся по SMART** (`reference/01-brief-and-copy.md`): что, сколько, к какому сроку.

Источники практик: [Deckary: roadmap slide](https://deckary.com/blog/roadmap-slide-powerpoint) · [Slideworks: how to write roadmap slides](https://slideworks.io/resources/how-to-write-roadmap-slides) · [SlideScience](https://slidescience.co/roadmap-slides/)

## Таблица: какой вопрос она отвечает

| Вопрос зрителя | Вид | Компонент-источник | Как собрать |
|----------------|-----|--------------------|-------------|
| «Кто лучше по многим показателям?» | **матрица с выделенной колонкой** | Bench Matrix `29454` | строки сгруппированы по смыслу (подпись группы повёрнута вертикально слева или висит над группой), колонка «наше» тонирована, лучшее значение в строке жирным, сноска «как читать» под таблицей |
| «Два показателя по каждому объекту» | **таблица-полосы** | Paired Bars `29470` | слева название, в центре две полосы на общей шкале (план — светлая, факт — акцент), справа значения; линии только сверху и снизу блока |
| «Что выбрать из вариантов?» | **сравнение с рекомендуемой колонкой** | Comparison Table `26827`, Feature Comparison `21218` | рекомендуемая колонка тоном, ✓ / — в ячейках, без рамок, одна линия под шапкой |
| «Как меняются показатели по регионам/каналам?» | **таблица с трендом в строке** | InlineAnalyticsTable `7475`, Sparkline `34510` | числа и мини-спарклайн или стрелка тренда в последней колонке, итог отделён толстой линией |
| «Сколько в каждой ячейке продукт × канал?» | **тепловая матрица** | эталон `heatmap-matrix` | насыщенность акцента по величине, итоги вне сетки |

Правила таблицы на слайде (Tufte, data-ink):
- **Ни рамок, ни зебры, ни заливок ячеек** (кроме тепловой матрицы и выделенной колонки). Порядок держат выравнивание, отступы и группировка.
- **Линии:** одна под шапкой, одна над итогом (толще), тонкие между группами, а не между строками.
- **Числа по правому краю,** табличные цифры, одна точность в колонке. Единицы в шапке, а не в каждой ячейке: «КД, млн ₽».
- **Текст по левому краю.** Шапка выровнена так же, как её колонка.
- **Одно выделение:** колонка «наше» или лучшая ячейка в строке, не больше.
- **На основном слайде не больше 7–8 строк.** Полная таблица уходит в приложение (`appendix-table`).
- **Пустая ячейка обозначается одинаково везде:** «—» или пусто, без смешения.

Источники: [Lines in tables (Masnick)](https://maxmasnick.nfshost.com/projects/datatips/guidelines/lines-in-tables) · [A List Apart: web typography tables](https://alistapart.com/article/web-typography-tables/)
