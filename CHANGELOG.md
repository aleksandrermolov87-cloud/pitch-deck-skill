В справочнике MagicPatterns инструменты ищутся по названию, а не по id коннектора.
- **`setup.sh` ставит всё нужное:** `--system` доставляет через Homebrew Node.js, Python 3.12, Google Chrome и poppler (`--with-libreoffice` — ещё LibreOffice); без флага называет недостающее и команду. Пакеты Node ставятся заново, если после обновления изменился `package-lock.json`. humanizer и taste-skill ставятся рядом со скиллом — и в `~/.claude/skills`, и в `~/.codex/skills`. `doctor.sh` проверяет Homebrew и версию Node.
- **SKILL.md переписан.** Таблица «Claude Code и Codex», восемь главных правил наверху, обязательные вопросы и 3D отдельными шагами (3D — стандартный шаг этапа 2 при ответе «Да»), этап 2 без путаной нумерации, единый раздел «Быстрые правки» и «Установка и обновление», исправлены устаревшие места (94 компонента, jsonschema). Описание скилла сокращено до 627 символов.

## 1.8.0 — 27.10.2026
Выразительные презентации и честная проверка (по фиче-реквесту после теста 1.5.0 и 1.7.1 на брифе о КАСКО) и 3D через двух провайдеров.
- **3D-объекты: MagicPatterns в Claude, встроенный `image_gen` в Codex** (`reference/09-3d-objects.md`, раздел 5). `prompt3d.py --provider codex-imagegen` выдаёт по одному вызову `image_gen` на картинку с прозрачным фоном; стиль и палитра у провайдеров общие, одна дека — один провайдер. Новый `scripts/visuals.py`: `choose` записывает выбор пользователя (без него картинка в деку не принимается), `fetch` качает только с CDN Magic Patterns, `import` берёт файлы только из `$CODEX_HOME/generated_images`, `list` предупреждает о картинках без записи. Происхождение (провайдер, инструмент, хэш промпта) — в `data/visuals.json`. `cutout.py` не режет PNG с готовой альфой. `config.json → image_provider: auto | magicpatterns | codex-imagegen | none`.
- **Честное сравнение версий.** `version_compare.py`: отсутствующий, старый или частичный манифест содержания больше не считается пустым — отчёт пишет «содержание не удалось сравнить» с причиной и не показывает фиктивных правок; вердикты по входам, пикселям, PPTX и среде не меняются.
- **Идентичность факта.** Факт в реестре различается по компоненту, пути, ряду, периоду и единице; `opt.show` понимает вложенные периоды и ссылки `series[0].values[5]`; `shown` проверяет связанную подпись, а не совпадение числа где-то на слайде. Существующие деки собираются теми же элементами, но реестр становится подробнее, и часть флагов `shown` честно сбрасывается.
- **Адаптивные числа.** `bigCompare` подбирает кегль числа и выносит единицу на отдельную строку, ниже порога останавливает сборку с советом другого компонента.
- **Частичные данные.** `rankingList`, `journeyMap` и `pricingTiers` принимают неполные данные («нет данных» или причина) без выдуманных значений в реестре фактов.
- **Точность долей.** `stackedShare`: `shareDigits`, режим подписи (`share` / `value` / `both`) и явный остаток (`known` / `computed` / `unknown`) с проверкой суммы.
- **Варианты компонентов.** `variants.py`: 2–3 варианта на слайд по смыслу и форме данных, причины исключений, показ в обеих темах и запись выбора; каталог полей `components/fields.json` (`reference/18-variants.md`).
- **Нативные диаграммы PowerPoint по выбору:** `nativeChart` (столбцы, линия, полосы) со встроенной таблицей «Изменить данные», единицами в формате ячеек и строкой происхождения; HTML-двойник рисует ту же геометрию фигурами, `pptx_audit.py` сверяет кэш диаграммы с таблицей. Библиотека — 95 компонентов.
- **Проверка в целевом приложении** (`pptx_target_check.sh`: PowerPoint на macOS или LibreOffice, ручной просмотр): переносы против HTML-двойника, переполнения, холст, картинки, подмена шрифта с версиями. Сводный отчёт показывает PPTX отдельно от HTML, по слайдам — компонент, причину выбора, данные, источник, ограничения и степень проверки, а также происхождение изображений по провайдерам.
- **Обновление установок без git.** `update.sh` скачивает релиз во временный клон, проверяет подпись ключом текущей установки, собирает и проверяет новую версию в промежуточной папке, переносит `config.json`, уроки и `*.local.md` побайтно, прежнюю версию оставляет резервной копией; откат — `--rollback --yes`. `check_update.sh` подсказывает этот путь архивным установкам.
- Решения по вопросам владельца: проверка в PowerPoint — необязательный профиль, не условие выпуска; встроенная книга диаграммы хранит категории, ряды, значения, единицы и источник без живой связи с моделью; внешняя генерация картинок — только после выбора пользователя; компоненты расширяются опциями с обратной совместимостью, новый компонент — только при другой форме данных.
- Новые тесты: `tests/version_compare`, `tests/update`, `tests/target_check`, `tests/variants`, `tests/visuals`, `tests/kasko/identity.sh`; `setup.sh --selftest` проверяет и каталог полей.

## 1.7.0 — 27.10.2026
Проверка содержания относительно брифа и честное сравнение версий навыка (по итогам теста 1.5.0 и 1.6.1 на брифе о КАСКО).
- **Полнота относительно брифа** (`reference/15-brief-coverage.md`, `scripts/brief_coverage.py`). На этапе 1 требования брифа выписываются в `requirements.json`: числа, периоды, выводы, обязательные места, запреты. На этапе 6 независимый сабагент заполняет карту «требование → слайд → элемент / заметки / нет». Скрипт проверяет карту по готовому PPTX и сам ищет числа и ключи требований на слайдах и отдельно в заметках. В `out/coverage.md` требования разложены по группам: на слайдах; изменено ради читаемости; только в заметках; нет или сокращено; исключено. Там же карта по всем слайдам.
- **Числа на графиках.** Каждое число из данных, которое компонент превратил в форму (высоту столбца, точку линии, ячейку), попадает в реестр фактов, даже без подписи (`auto`). Источник берётся из данных компонента. `build.js` отмечает у факта `shown`: читается ли число на слайде. `facts_check.py` различает «влияет на график» и «можно прочитать». `brief_coverage.py` пишет «влияет на график слайда N, но его нельзя прочитать», если бриф требует показать такое число.
- **`opt.show` у любого компонента**: число, которое бриф требует показать, подписывается строкой под графиком, если компонент не подписал его сам.
- **Сравнение версий навыка** (`reference/16-version-compare.md`, `scripts/version_compare.py`).
  - Прогоны и сравнения пишутся в новые папки: PPTX и PNG обеих тем, исходники, манифест с версией, коммитом и средой. Для каждого слайда есть пара «до / после» и карта разницы.
  - Сравнение называет себя контрольным, только если менялись лишь сборщик и компоненты.
  - Правки содержания (компоненты, тексты, заметки) показываются по слайдам отдельно и не приписываются версии навыка.
- **Сводный отчёт проверок** (`reference/17-check-report.md`, `scripts/check_report.py`).
  - Пять разделов, у каждого описана граница проверки: реестр фактов по источникам; полнота относительно брифа; переполнения, геометрия и библиотека; просмотр в PowerPoint; предупреждения с объяснением (`out/waivers.json`).
  - Кроме разделов: версия и коммит навыка, компоненты по слайдам, отличия от предыдущей сборки.
  - `render.sh` пишет итог в `out*/render.json`.
- **Приёмочный тест** `tests/kasko/run.sh`. Тестовая дека «КАСКО в России» из 12 слайдов на условных данных собирается в двух вариантах: с потерями из теста и исправленная. Проверяются все критерии приёмки. `release.sh` запускает тест перед выпуском.
- Библиотека: в `stackedShare` подпись сегмента ставится внутри, только если имя влезает в сегмент. Процентные данные больше не подписываются дважды.
- Пакет: локальные журналы правок (`learnings/copy_edits.jsonl`, `bg_edits.jsonl`) и прогоны приёмки не попадают в установочный архив.

Рубрика 0–3: небанальность, передовость, совместимость с брендом, честность данных; ворота «бренд ≥ 2, честность ≥ 2». Первый публичный релиз на GitHub, по итогам аудита безопасности.
- **Установка и обновление из git:** `git clone` релиза-тега, `scripts/update.sh` показывает изменения в скриптах и инструкциях агента и переключает на новый релиз только с `--yes`; `scripts/release.sh` выпускает версию (проверки, тег, релиз с установочными md и SHA-256).
- **Агентская безопасность:** раздел «Безопасность» в SKILL.md — внешний контент как данные, без команд и ссылок из вводных, скачивание только с CDN Magic Patterns, во внешние сервисы только обобщённое, необратимое только с подтверждения; из шага Figma убраны JavaScript на странице и доступ к Finder.
- **Скрипты:** значения в `node -e` передаются только через аргументы (`scripts/jget.sh`), проверка имён папок, режима, групп галереи и вердиктов оценок; impeccable не ищется в папке проекта; картинки слайдов только из `img/`; Chrome с песочницей, временный профиль через `mktemp`, CSP в HTML-двойнике, экранирование атрибутов.
- **Шрифт:** только https, необязательный `FONT_SHA256`, распаковка только .otf/.ttf без путей и ссылок.
- **Цепочка поставок:** `requirements.txt` с версиями (+ defusedxml), `package.json` и `package-lock.json`, `npm ci --ignore-scripts`; демо-3D только с `https://cdn.magicpatterns.com/`, с ограничением размера и сверкой sha256, если он указан.
- **Утечки:** `scripts/leakcheck.sh` (ключи, токены, личные пути + локальный список `scripts/leaks.local.txt`), pre-commit-хук, CI на GitHub Actions; `.gitignore` для всего локального.
- **Установка из md:** распаковка во временную папку с проверкой записей архива, хэш сверяется с релизом на GitHub.
- Примеры и демо-данные обезличены: вымышленные числа и названия каналов.
- README, LICENSE (MIT), THIRD_PARTY.md, SECURITY.md, CODEOWNERS.
