# Инфографика: подбор под данные и помощь там, где 21st Magic не нашёл компонент

## Выбор формы

Используй график, схему, экран или текстовую композицию по вопросу зрителя и данным. Текстовый слайд и таблица допустимы без декоративной графики. 3D-объект нужен только когда он соответствует задаче и выбранному визуальному направлению; не добавляй его для прохождения проверки.

`pptx_audit.py` выдаёт предупреждения о текстовых слайдах и контейнерах по формальным признакам. Проверь читаемость и смысл, зафиксируй решение в отчёте. Доля визуальных слайдов и повтор формы не являются самостоятельной гарантией качества.

## Подбор: форма данных → инфографика

| Что нужно показать | Инфографика (архетип) | Когда не подходит |
|--------------------|-----------------------|-------------------|
| одно главное число | число-герой + спарклайн тренда или пиктограмма масштаба (`kpi-hero`) | если чисел больше 4, нужен ряд или bullet-chart |
| план против факта | bullet-chart: серая полоса плана, акцентная полоса факта, отметка цели (`plan-fact`) | без плана используй тренд |
| изменение во времени | столбики со значениями и скобкой роста (`bars-trend`), slope-chart для двух точек | больше 24 точек: линия |
| доля целого | полоса долей (`stacked-share`), пиктограммная сетка 10×10 для одной доли | 5+ частей, мелкие хвосты сгруппируй в «прочие» |
| сравнение категорий | горизонтальные столбики по убыванию, значения справа | категорий больше 12: топ-8 и «прочие» |
| два измерения (продукт × канал) | тепловая матрица (`heatmap-matrix`) | меньше 3×3 — просто столбики |
| вклад в итог | водопад: база, плюсы, минусы, итог | без разложения итога не нужен |
| воронка или конверсия | ступени воронки с конверсией между ними (`funnel`) | этапы не последовательны — столбики |
| процесс или путь клиента | последовательные шаги и время, когда оно известно (`process-steps`) | больше 6 шагов — сгруппируй |
| связи ролей | схема-хаб (`hub-diagram`) | без связей — карточки |
| расписание | гант с фазами (`gantt-lanes`), роадмап (`timeline-months`, `roadmap-quarters`) | — |
| позиционирование | матрица 2×2 (`competition-2x2`) | без реальных осей не делать |
| продукт | карточка продукта с имеющимися показателями или экраном (`product-card`) | — |
| масштаб в понятных единицах | пиктограммы: «1 значок = 1 000 полисов» | точность важнее образа — столбики |

## Когда 21st Magic не дал компонент

Сначала библиотека: почти каждая строка таблицы выше уже есть готовым компонентом (`components/README.md`). Порядок ниже нужен для слайда, которого нет ни в библиотеке, ни в 21st.

Это обычная ситуация, а не повод сделать простой слайд. Порядок:
1. **Переформулируй запрос** через форму данных, а не тему: не «insurance products», а «grouped table with inline bar per group and status dots». Сделай 2–3 попытки, включая `get_inspiration` с полным описанием слайда.
2. **Возьми ближайший по структуре** компонент, даже из чужого домена: дашборд, расписание, прайс-таблицу. Перенеси из него структуру.
3. **Собери по рецепту** из примитивов (`rect / oval / line / text / image`) по таблице выше. Рецепты лежат в `patterns/slide-archetypes.md`, эталоны — в `learnings/gallery/good/`.
4. **Сгенерируй два варианта раскладки** (`ONLY=<n> node build.js`, два PNG), выбери лучший по композиции.
5. Если данных для инфографики нет совсем, слайд несёт **контекстный 3D-объект** (`hero`) или экран продукта.
6. В `components.md` запиши: «21st: запросы …, кандидатов нет / не подошли, потому что …; собрано по рецепту X».

## Рецепты из примитивов (коротко)

- **Bullet-chart:** дорожка `rect` (fill `rule`), полоса плана (`bar`, 60% высоты), полоса факта (`accent`, 35% высоты), отметка цели `vline` 2 pt. Значение справа, отклонение со знаком.
- **Пиктограммная сетка 10×10:** 100 `oval` 0,12″ с шагом 0,18″, закрашено N штук акцентом, остальные `rule`. Подпись «N из 100».
- **Водопад:** столбики от предыдущего уровня, плюсы `accent`, минусы `muted`, итог `ink`, пунктирные связки между вершинами.
- **Slope-chart:** две вертикальные оси, линии между значениями. Растущие линии акцентом, остальные `muted`, подписи на концах.
- **Пиктограммы масштаба:** один 3D-стикер продукта, повторённый N раз в ряд (масштаб в подписи). Используй, только если N ≤ 20.
- **Спарклайн к KPI:** 12 точек `line`-сегментами 1,25 pt под числом, последняя точка `oval` акцентом.

## Плотность и насыщенность

- На слайде один главный визуальный элемент, остальное ему подчинено.
- Текст рядом с инфографикой объясняет вывод, а не пересказывает числа.
- «Насыщенно» не значит «больше элементов». Это значит, что каждый элемент кодирует данные или смысл. Декоративная графика без смысла остаётся слопом (taste-skill).
