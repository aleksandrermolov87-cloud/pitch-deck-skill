# 3D-объекты (MagicPatterns в Claude, image_gen в Codex): строго по контексту слайда

Объект на слайде должен рассказывать **именно этот слайд**. Если его можно без потерь перенести в
чужую деку, это слоп, и он не годится. Каждый объект собирается из контекста слайда по шагам ниже,
а промпт строит `scripts/prompt3d.py`. Руками промпт не пишется, чтобы палитра и стиль не расползались.

## 1. Контекст → бриф объекта

По каждому слайду, где нужен объект, заполни бриф (`src-<тема>/data/objects3d.json`, формат ниже):

| Поле | Откуда берётся | Пример (ОСАГО для бизнеса) |
|------|----------------|----------------------------|
| `entity` | сущность слайда: продукт, канал, сегмент, статус, шаг процесса, метрика | ОСАГО для ЮЛ и ИП |
| `facts` | 1–3 конкретных признака **из данных слайда**: аудитория, триггер, канал, бандл, число | «машины компании или автопарк», «бизнес-карта с тратами на топливо» |
| `object` | предметный носитель смысла: вещь из мира аудитории, а не абстракция | компактный фургон и легковая машина компании |
| `details` | 1–2 детали, которые привязывают объект к `facts` | маленький щит над крышей; топливная карта у колеса |
| `meaning` | что объект должен сообщить зрителю одной фразой | «страховка всего автопарка компании» |
| `placement` | роль на слайде: `card`, `hero`, `row`, `sticker`, `bg` | `card` |
| `trace` | откуда взят каждый признак: лист и ячейка, слайд-источник, строка карточки | `cards.json → osago → ЦА, Бандл` |

Правило проверки: убери `facts` и `details`. Если объект всё ещё подходит слайду, он слишком общий. Добавь признак из данных.

## 2. Словарь предметных метафор (банк и страхование для бизнеса)

Используй как старт и уточняй признаками из данных. Не бери строку как есть.

| Сущность | Объект | Детали, которые делают его конкретным |
|----------|--------|----------------------------------------|
| Коробочный ДМС | коробка-набор с медицинским крестом | крышка приоткрыта, внутри карточки сотрудников; фиксированная цена — бирка без цифр |
| Классический ДМС | медицинский кейс | стетоскоп, знак бесконечности на замке (без лимита приёмов) |
| Мини-ДМС, подписка | компактная медкарта | кольцевая стрелка ежемесячного продления, маленький смартфон с телемедициной |
| Модульное страхование | блоки-модули, которые стыкуются в один полис | на модулях крест (ДМС), дом (имущество), щит (ответственность) |
| Имущество арендатора | фасад небольшого магазина или кафе с маркизой | щит над витриной, капля воды и язычок огня — риски |
| Встроенное к карте и депозиту | банковская карта рядом с ячейкой вклада | щит на углу карты, замок на ячейке |

| НИБ (интернет-банк) | ноутбук или смартфон с карточкой продукта | условный интерфейс без текста, щит на экране |
| Менеджер (SFA) | планшет менеджера и гарнитура | карточка клиента на экране без текста |
| Отделение, офис | стойка обслуживания | табличка без текста |
| Рост КД | ступени-столбики | последний столбик в акцентном цвете, монеты на верхнем |
| Пилот | маленький стенд с флажком старта | секундомер (короткий срок 2–3 месяца) |
| Риск сработал / есть риск / нет риска | треугольник «!» / песочные часы / щит с галочкой | — |
| Нужно решение | документ с ручкой и печатью | — |
| Достижение | кубок | только для итогов, не для продуктов |

## 3. Запреты (дженерик-объекты)

Без явной смысловой связи с данными **запрещены**: ракета, лампочка, мишень со стрелой, рукопожатие,
шестерёнка, глобус, пазл (кроме модульности), лупа (кроме анализа), шахматы, облако, мозг,
абстрактные сферы и кубы, персонажи-человечки. `prompt3d.py` блокирует их, если в брифе нет поля `allow_generic` с причиной.

Ещё запрещено:
- один объект на нескольких сущностях деки;
- объект с надписью, цифрами или логотипом (промпт это запрещает, проверяй глазами);
- объект, который спорит со статусом (зелёная галочка на риске).

## 4. Единый стиль набора

Все объекты деки генерируются **одной пачкой** с одной стилевой строкой из `theme.json → prompt3d`:
материал, свет, ракурс, тень и палитра одинаковые. Если объект досоздаётся позже, бери ту же стилевую
строку без изменений.

| placement | Размер на слайде | Ракурс | Фон генерации |
|-----------|------------------|--------|---------------|
| `card` | 1,1–1,4″ в правом верхнем углу карточки | 3/4, лёгкий наклон | чисто белый → вырезка |
| `hero` | 3,5–4,5″, правая колонка | 3/4, крупный план | чисто белый → вырезка |
| `row` | 1,6–2,0″, ряд шагов процесса | фронтально, одинаковый масштаб | чисто белый → вырезка |
| `sticker` | 0,6–0,9″, у числа или заголовка | фронтально | чисто белый → вырезка |
| `bg` | натюрморт на весь слайд или колонку | композиция справа-снизу, обрез краем | ровный цвет фона слайда (hex), без вырезки |

## 5. Генерация: два провайдера, один стиль

Кто рисует, решает среда и выбор пользователя, а не агент молча:

| Среда | Провайдер (`config.json → image_provider: auto`) | Инструмент | Пачка |
|-------|------------------------------------------------|------------|-------|
| Claude (Code, desktop) | `magicpatterns` | MagicPatterns `generate_image` (Magic OS) | до 5 картинок за вызов |
| Codex | `codex-imagegen` | встроенный `image_gen` (системный скилл `imagegen`) | один вызов на картинку |

`image_provider` можно закрепить явно (`magicpatterns`, `codex-imagegen`) или выключить (`none`: 3D нет, слайды закрывают инфографика и экраны).
CLI-режим `imagegen` (`scripts/image_gen.py`, нужен `OPENAI_API_KEY`) скилл сам не включает: только если пользователь попросил его сам.

**0. Ответ на обязательный вопрос планировщика.** Нужны ли 3D в этой деке, спрашивается всегда, на этапе 0 (SKILL.md, «Обязательные вопросы планировщика»): «Да, через <провайдер среды> (Recommended)» / «Нет, без 3D». Лимит или стоимость показывается, если известны. Ответ записывается сразу после одобрения плана:
```bash
$SKILL/.venv/bin/python -I $SKILL/scripts/visuals.py choose src-<тема> --provider <magicpatterns|codex-imagegen|none>
```
Без записи `visuals.py` не примет картинку: генерация без ответа пользователя невозможна по построению. В промпт уходят только `object`, `details`, `meaning` и стиль: без чисел, имён клиентов и внутренних названий. При ответе «Нет» слайды закрывают инфографика и экраны продукта, бан простых слайдов действует.

**1. Промпты.**
```bash
$SKILL/.venv/bin/python -I $SKILL/scripts/prompt3d.py src-<тема>/data/objects3d.json --theme src-<тема>/theme.json \
  --provider <magicpatterns|codex-imagegen> --variants 2 --out src-<тема>/out/prompts3d.json
```
Скрипт проверяет бриф (признаки из данных, запреты, дубли объектов) и печатает промпты: для MagicPatterns пачки `{images: [{name, aspectRatio, prompt}]}`, для Codex список `{calls: [{name, size, prompt}]}`, плюс таблицу трассировки. Стилевая строка и палитра у провайдеров одна, но **одна дека — один провайдер**: объекты разных генераторов не совпадут по свету и материалу.

**2а. MagicPatterns (Claude).**
1. `list_os` / `create_os {name: "<Дека> — графика"}` → `osId`.
2. `generate_image {osId, images}` по пачкам из `prompts3d.json`, не больше 5 картинок за вызов. Больше — несколько вызовов в одном сообщении.
3. Каждый URL из ответа: `visuals.py fetch src-<тема> --url <url> --name <name> --slide <N> --payload src-<тема>/out/prompts3d.json`. Скрипт качает только с `https://cdn.magicpatterns.com/`, до 20 МБ, проверяет, что это картинка, и пишет происхождение.

**2б. Codex `image_gen`.**
1. Один вызов `image_gen` на картинку из `calls`: промпт как есть, размер из `size`, прозрачный фон (промпт его уже просит). Вызовы независимы, отправляй их подряд без ожидания.
2. Codex сохраняет результат в `$CODEX_HOME/generated_images/…`. Каждую картинку перенеси в проект: `visuals.py import src-<тема> --file <путь из ответа> --name <name> --slide <N> --payload src-<тема>/out/prompts3d.json`. Скрипт принимает файлы только из этой папки и пишет происхождение. Картинка, на которую ссылается дека, не должна остаться только в папке Codex.
3. Если `image_gen` недоступен, скажи об этом. CLI-режим и другие провайдеры — только по просьбе пользователя.

**3. Вырезка.** `cutout.py <img> --preview` для всех, кроме `bg`. MagicPatterns отдаёт белый фон, его скрипт вырезает. Прозрачный PNG от `image_gen` скрипт не режет: обрезает поля, считает `fill` и делает превью. Посмотри `*_check.png`: края без белого ореола на тёмном и светлом фоне.

**4. Происхождение в отчёте.** `visuals.py list src-<тема>` печатает картинки по слайдам с провайдером и предупреждает о файлах в `img/3d/` без записи. Сводный отчёт (`check_report.py`) берёт `data/visuals.json`: картинка `image_gen` никогда не подписывается как работа MagicPatterns, демо-объекты заготовки помечены `demo`. Картинка пользователя: `visuals.py record src-<тема> --file img/3d/<файл> --slide <N>`.

**5. Выбор варианта** по чек-листу:
   - смысл считывается в размере на слайде (уменьши превью до 1,2″);
   - в нём есть детали из `details`;
   - палитра только из темы, без надписей;
   - силуэт отличается от других объектов деки;
   - по стилю объект совпадает с остальными объектами набора.
   Если оба варианта не проходят, уточни `details` и сгенерируй заново. Не бери «почти подходящий».
   Доработка выбранного: в MagicPatterns `referenceImages` с его URL, в Codex — `view_image` по файлу и правка тем же `image_gen`; результат снова через `fetch` / `import` под новым именем `<name>_v3`.
**6. Вставка:** `place3d()` из `lib.js` по правилам раздела 6: якорь, оптический размер, посадка. В `components.md` запиши строку трассировки и якорь.

## 6. Размещение на слайде (отдельный шаг, не «куда влезло»)

Генерация отвечает за **что** изображено, размещение — за то, **как объект встроен в композицию**. Плохо размещённый хороший объект читается как слоп: стикер, висящий в пустоте.

### 6.1 Якорь: объект живёт рядом с тем, что изображает
Перед размещением запиши якорь: элемент слайда, который объект поясняет.

| Что изображает объект | Якорь | Где стоит объект |
|-----------------------|-------|------------------|
| продукт карточки | тайл продукта (KPI-панель, карточка) | **внутри** тайла, сверху, по его оси, как фото товара на карточке |
| шаг процесса | подпись шага | над подписью, по центру колонки шага |
| число-герой | число | справа от числа на его базовой линии или под ним |
| тема всей деки | обложка | своя колонка `hero`, по центру высоты блока заголовка |
| статус или риск | точка статуса или подпись | рядом со статусом, размер `sticker` |

**Нельзя:**
- свободное поле шапки между заголовком и знаком бренда;
- зона знака бренда и фирменных полос;
- поверх текста;
- «где осталось место» без связи с якорем.

### 6.2 Геометрия
- Объект выравнивается по оси или краю якоря: центр колонки, левый край тайла, базовая линия числа.
- До ближайшего текста не меньше 0,15″, до края контейнера не меньше 0,2″.
- В серии (все карточки, все шаги) объект стоит **в одной и той же точке якоря**, а нижний край идёт по одной линии: объекты «стоят» на одной базе.

### 6.3 Оптический размер, а не размер рамки
Высокий узкий и низкий широкий объекты в одинаковом боксе выглядят разного размера. `cutout.py` пишет рядом с PNG файл `<имя>.json` с долей видимых пикселей (`fill`). Помощник `place3d()` подбирает масштаб так, чтобы **видимая площадь** у объектов серии была одинаковой (± 10%), не выходя за зону якоря.

### 6.4 Посадка
- На тёмной теме под объектом мягкое свечение цвета акцента (эллипс 15–20% непрозрачности), иначе объект «висит».
- На светлой теме белый объект на светлом тайле теряется. Тайл под объектом делается тоном темнее (`card`) или объект генерируется с более тёмными деталями. Проверяй контраст в обеих темах.

### 6.5 Два варианта и выбор
Для архетипа сделай 2 варианта размещения (например, «внутри тайла сверху» и «у числа»), отрендерь один слайд (`ONLY=<n>`) и выбери по критериям:
- связь с якорем считывается без подписи;
- объект не спорит с заголовком и числом-героем: он вторичен по весу;
- серия выглядит единообразно на контакт-листе.

### 6.6 Проверка
`pptx_audit.py` проверяет каждую картинку:
- **ERR:** объект перекрывает текст;
- **WARN «оторван от содержания»:** до ближайшего элемента содержания больше 0,5″, кроме обложки;
- **WARN «в зоне бренда»:** объект в зоне знака или полос;
- **WARN «серия разного размера»:** видимая площадь объектов в одной позиции на разных слайдах отличается больше чем на 25%.

## 7. Формат брифа `objects3d.json`

```json
{ "deck": "Продукты 2027", "objects": [
  { "name": "osago_fleet", "slide": 11, "entity": "ОСАГО для ЮЛ и ИП",
    "facts": ["машины компании или автопарк", "бизнес-карта с тратами на топливо"],
    "object": "a compact delivery van and a small company car parked side by side",
    "details": ["a small glossy shield floating above the van roof", "a fuel card leaning against the front wheel"],
    "meaning": "insurance for the whole company fleet",
    "placement": "card", "trace": "cards.json → osago: ЦА, Бандл" }
]}
```
`object`, `details` и `meaning` пишутся по-английски: генератор лучше понимает английский. `facts` и `trace` пишутся по-русски, для проверки и отчёта.
