# Этап 7. Обучение: оценки слайдов в пару кликов

Цель: после каждой деки пользователь отмечает, какие слайды получились, а какие нет. Хорошие становятся
эталонами (PNG и код функции слайда), плохие с причиной копятся и превращаются в правила. Следующая дека
на этапах 0, 3 и 6 начинается с чтения `learnings/LESSONS.md`.

## Порядок

1. **Контакт-лист и вопросы:**
   ```bash
   $SKILL/.venv/bin/python -I $SKILL/scripts/learn.py sheet src-<тема>
   ```
   Скрипт пишет `out/review/sheet.png` (все слайды сеткой, у каждого номер и архетип) и печатает JSON с готовыми пачками вопросов.

2. **Покажи слайды:** `SendUserFile` с `sheet.png` (display: render), чтобы пользователь видел все слайды сразу.

3. **Первый клик — общий вопрос** (`AskUserQuestion`, один вопрос):
   - «Все хорошие — в эталоны (Recommended)», если на этапах 4–6 не осталось оговорок;
   - «Отмечу по слайдам»;
   - «Пропустить обучение».

   Если ответ «Все хорошие», все слайды пишутся как good, переходи к шагу 5.

4. **Оценка по слайдам:** вызывай `AskUserQuestion` с пачками из JSON, по 4 вопроса за вызов, multiSelect. В каждом вопросе варианты «Хорошо», «Плохо: композиция», «Плохо: текст», «Плохо: данные», а через «Other» можно написать комментарий. На деку из 12 слайдов уходит 3 экрана кликов.
   - Если выбрано «Хорошо» вместе с «Плохо: …», считай слайд хорошим с замечанием (verdict good, reasons заполнены).
   - Текст из «Other» сохраняется в `comment`.

5. **Запись:**
   ```bash
   $SKILL/.venv/bin/python -I $SKILL/scripts/learn.py record src-<тема> --ratings '{"1":{"verdict":"good"},"4":{"verdict":"bad","reasons":["композиция"],"comment":"пусто справа"}}'
   ```
   - `learnings/ratings.jsonl` получает строку на слайд (дека, архетип, компоненты `lib` из `out/slides.json`, версия навыка, заголовок, вердикт, причины, комментарий);
   - `learnings/gallery/good|bad/` получает PNG, у хороших ещё и `.js` с функцией слайда;
   - `learnings/LESSONS.md` пересобирается: «Что работает у вас», по архетипам эталоны и причины, «кандидаты в правила»;
   - `learnings/prefs.json` пересобирается: доля хороших по компонентам и архетипам (ниже), её читает `variants.py suggest`.

6. **Закрепление.** Если в LESSONS.md появился кандидат в правило (причина вероятнее всего встречается больше чем на половине слайдов архетипа, см. «Модель»):
   - сформулируй правило одной строкой и спроси через `wrap_up` (кнопки «Добавить правило» / «Не надо»), добавить ли его в `reference/05-taste-pass.md`, `04-grid-impeccable.md` или `brands/<бренд>.md`;
   - если вывод касается вкуса пользователя в целом («не люблю пустоты справа»), сохрани его и в память как `feedback`.

7. **Плохие слайды этой деки** не оставляй как есть: предложи переделку прямо в этом ходе (вопрос в `wrap_up` с кнопкой «Переделать слайды N, M»).

## Модель

Оценок мало (десятки), поэтому счёт заменён байесовской оценкой доли, которая честно показывает неуверенность.

- **Доля хороших** у архетипа и у компонента — Beta-Binomial с априорным Beta(1,1): среднее `(хорошие + 1) / (n + 2)`
  и интервал 80% (выборка numpy с фиксированным зерном: на тех же данных тот же результат).
- **Компонент** получает вердикт слайда, на котором стоит (`lib`). Старые оценки без `lib` идут только в архетипы.
- **Выборы вариантов**: `variants.py pick` пишет `learnings/picks.jsonl` (дата, дека, слайд, выбранный, показанные).
  Выбранный +1 к хорошим, показанный рядом и не выбранный +0,5 к плохим (мягкий отказ: мог быть и хорош). На слайд прогона
  считается последний выбор.
- **Кандидат в правило** — только если P(доля слайдов архетипа с этой причиной > 0,5) ≥ 0,8, а не «2 раза»: 2 плохих из 10
  не правило, 2 из 2 и 3 из 3 правило (P = 0,88 и 0,94), 1 из 1 нет (0,75). Так же для архетипа в целом (причины разные) и для компонента
  (P(доля хороших < 0,5) ≥ 0,8). Под порогом причина видна в «Что не нравилось» с этой вероятностью.
- **Эталоны** архетипа: сначала слайды на компонентах с большей долей хороших, затем свежие.
- **«Что работает у вас»**: компоненты с n ≥ 2 по доле хороших, с интервалом.
- **Подбор**: `variants.py` прибавляет к счёту кандидата `1,5 × (доля − 0,5) × n/(n + 5)` и пишет в таблице «по вашим оценкам:
  +0,4». При паре оценок поправка почти нулевая, без `prefs.json` счёт прежний (`reference/18-variants.md`).

Тест: `zsh $SKILL/tests/learn/run.sh` (синтетические оценки и выборы во временной `PITCH_LEARN_DIR`).

## Как уроки используются дальше

- **Этап 0:** в плане есть строка «Уроки», из LESSONS.md берутся эталоны по нужным архетипам и действующие правила.
- **Этап 2:** `variants.py suggest` поднимает компоненты, которые вам нравились, и опускает отклонённые (`prefs.json`). Если для архетипа есть эталон, начинай с его `.js` из `learnings/gallery/good/`, а не с нуля. 21st нужен только для того, чего в эталонах нет.
- **Этап 5:** причины из «Что не нравилось» добавляются в чек-лист этой деки.

## Форматы

`ratings.jsonl`, строка:
```json
{"date":"2026-10-26","deck":"Каналы_и_продукты_2027","slide":3,"fn":"matrix","archetype":"heatmap-matrix",
 "title":"КД и шт. по каналам","verdict":"good","reasons":[],"comment":"","png":"…/gallery/good/….png",
 "lib":["heatmap"],"skill":"1.10.1"}
```
`picks.jsonl`: `{"date","deck","src","run","slide","chosen","variant","shown":[…],"demo","skill"}`.
`prefs.json`: `{"components": {имя: {good, bad, picks, rejects, n, mean, lo, hi, p_hi}}, "archetypes": {…}, "updated"}`,
`p_hi` — P(доля хороших > 0,5). Все три файла локальные: в git и пакет не входят.
Архетип берётся из поля `archetype`, которое возвращает функция слайда в `slides.js`. Если его нет, используется имя функции. Ставь архетипы из `patterns/slide-archetypes.md`, тогда уроки накапливаются между деками.
