# Смысловой выбор и Impeccable для презентаций

Читай при новой структуре, выборе схемы и сравнении версий. Для точной замены цены этот маршрут не нужен. `suggest` — поиск кандидатов по форме данных, не оценка истинности отношений и не автоматический арт-директор.

## Контракт выбора

До рендера запиши на слайд одну компактную строку или запись; результаты последнего поля заполни после просмотра:

| Поле | Что должно быть записано |
| --- | --- |
| Задача | Вопрос зрителя и один ответ, который даёт слайд |
| Данные | Какие сущности и отношения реально заданы, источник; чего нет |
| Визуальная семантика | Что означает каждая стрелка, ось, площадь, порядок, размер и чёрный акцент |
| Кандидаты | Выбранный и ближайший конкурент, необходимые поля, причина принятия/отказа |
| Проверка рендера | Что зритель должен прочитать первым, масштаб относительно референса, найденный дефект и исправление |

Порядок выбора:

1. **Смысл.** Вначале исключи неверные отношения: процесс требует последовательности, дерево — условий, ранжирование — сопоставимой меры. Три поля «охват / находки / покрытие тестами» не становятся процессом из-за наличия трёх подписей. Нет отношения в источнике — нет стрелки. Подходит открытая группировка или таблица. Не добавляй фиктивные результаты ради заполнения компонента.
2. **Полнота и контракт.** Кандидат должен сохранять обязательные сущности, условия, возвраты и ограничения. Отсутствующие обязательные данные исключают кандидата либо требуют явно обозначенной неполноты. Красота не компенсирует потерю скоупа.
3. **Читаемость.** На реальном тексте сравни масштаб рабочей схемы, длины строк, число переводов взгляда и главный акцент. Векторность, соответствие JSON-контракту и отсутствие наложений не подтверждают понятность.
4. **Композиция.** Среди прошедших кандидатов выбери самый ясный для аудитории и согласованного референса. Прямое библиотечное исполнение не обязано выигрывать у честно названной адаптации. Не усложняй открытый список связями ради «инфографики».

При неопределённости — два рендера на одинаковом содержании; не сравнивай эффект дизайна одновременно с добавлением/удалением смыслов. При ясном выборе достаточно записать причину, без ритуальной генерации вариантов. Интеллектуальный выбор — работа с отношениями и чтением, а не повышение температуры модели или суммарный псевдоточностный балл.

## Impeccable как рабочий проход

1. Найди установленный скилл через `zsh "$SKILL/scripts/impeccable.sh" --where`. Прочитай **его** SKILL.md: версии и команды различаются. Запусти context один раз на сессию в корне проекта по его правилам. Существующий контекст и утверждённый бриф используются без повторного интервью. Не меняй глобальные hooks и не устанавливай зависимости автоматически.
2. Для редизайна/аудита прочитай применимые `reference/critique.md` и `layout.md`; перед правками `craft-floor.md`; перед выдачей `polish.md`. Это инструкции агенту, не гарантия существования CLI-команд `critique` или `polish`. Выполни их смысловую работу над отрендеренными страницами.
3. Сохрани в существующем отчёте **замечание → страница/элемент → причина → исправление → проверенный рендер**. Минимум: порядок чтения, группировка, ритм, масштаб, смысл акцента, фон и повторы заголовка/схемы/нижнего вывода. Сравни рабочее содержание с референсом, а не только шрифт и цвет. Крупный заголовок не должен вытеснять схему в мелкую центральную полосу.
4. Детектор запускается по правилам context установленной версии; при активном hook не дублируй скан. Сохрани команду, вывод, применимость. Нулевой вывод на SVG/HTML — только отсутствие найденных этим сканером сигналов. Он не проверяет смысл связей, не подтверждает качество PDF и не закрывает визуальный проход.
5. Для PDF/PPTX адаптируй web-правила: проверяй страницы при обычном размере просмотра, длинный реальный текст, контраст и близость подписей. Hover, breakpoints, loading и анимации статическому документу не приписывай. Размеры rem, лимит display 6rem и карточки интерфейса механически не переноси. Сохрани заданные шрифт, тему, формат и число страниц.
6. Просмотри итоговый экспорт, исправь замечания и проверь снова изменённые места вместе с монтажом. При недоступном Impeccable выполни собственный явно обозначенный проход; отсутствие инструмента и границы проверки — в отчёт. Не называй его полным использованием внешнего скилла.

## Честное сравнение

Разделяй наблюдаемое улучшение, подтверждённый механизм (код компонента, контракт, проверка) и причинный вывод. Новый шрифт, старые принятые фоны или ручная редактура не являются доказательством пользы обновления. Без одинаковых входов и условий это редакционное сравнение, не A/B-тест. Сохрани и удачные решения прежней версии: новый вариант не получает преимущества за новизну.

При повторных структурных замечаниях используй `reference/24-composition-lab.md`: контроль и альтернативы топологии на одном содержании, задачи чтения, рендер и привязанное к нему независимое ревью.
