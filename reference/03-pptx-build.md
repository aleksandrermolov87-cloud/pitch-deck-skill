# Этап 3. Сборка PPTX

## Почему так, а не python-pptx по шаблону

- **pptxgenjs** создаёт настоящие фигуры и текстовые поля, поэтому в PowerPoint всё правится руками.
- **HTML-двойник** (`out/deck.html`) получается из той же разметки. По нему headless Chrome снимает PNG и меряет, влез ли текст в бокс, а impeccable проверяет вёрстку. Без двойника переполнение видно только после открытия файла в PowerPoint.
- **Реестр фактов** (`out/facts.json`) хранит адрес источника у каждого числа на слайде. Без него сверка превращается в «посмотрел глазами».

Если пользователь прислал свой .pptx и просит «сохранить слайды, добавить новые»:
- не пересобирай его слайды. Новые собери отдельно и вставь в его файл через python-pptx (копирование частей слайда и связей) или попроси вставить вручную;
- перед правкой положи копию в `user-edits/<дата>/`;
- ручные правки пользователя (порядок, заголовки, снятые сноски) перенеси в `deck.json` и `slides.js`, чтобы пересборка их не потеряла.

## Файлы проекта (`zsh $SKILL/scripts/new_deck.sh src-<тема> "<Название>"`)

| Файл | Что внутри |
|------|-----------|
| `theme.json` | шрифты, холст и поля, шкала кеглей, палитры dark/light, полосы фона |
| `deck.json` | имя файла, заголовок, скрытые слайды |
| `lib.js` | примитивы `rect/oval/hline/vline/image/text`, `chrome()` — шапка, `fact()/mln()/fmt()` |
| `components.js` | библиотека компонентов тела слайда (`components/README.md`): роадмапы, таблицы, графики, схемы; числа регистрирует сама |
| `slides.js` | функции слайдов → `{ bg, els, hidden?, notes? }`, экспорт `S: [...]` в порядке показа |
| `data/` | контракт данных (JSON из extract-скрипта), бриф, тексты |
| `bg.py` | фоны `img/bg_*.jpg` и светлые `img/bgL_*.jpg` |
| `build.js` | PPTX + `out[-light]/deck.html` + `out/facts.json` |
| `render.sh` | PNG `out/png/` (или `png@2x` при `SCALE=2`) + `{slides, font, overflow}` |

## Правила разметки

- Координаты в дюймах на холсте 13,333 × 7,5. Шаг 0,05″, функция `snap()`.
- Высоту текстового бокса считай по числу строк: `ceil(tw(текст, кегль) / ширина) × кегль × 1,2 × ls / 72`. Запас 5–10%.
- Карточки в одном ряду одной высоты: считай высоту по самой длинной и применяй ко всем.
- Слайд, у которого количество элементов зависит от данных (2–6 карточек), раскладывай формулой, а не набором ручных координат.
- Акцентный цвет только из `C.accent`. Никаких hex в `slides.js`.
- В функции слайда никаких чисел-литералов, кроме координат. Значения берутся из `data/` через `fact()`.
- `id` у важных текстов (`s3-title`) нужен, чтобы `render.sh` назвал переполненный бокс понятно.
- `notes` — заметки докладчика: что говорить по слайду, если дека для показа вживую.

## Числа

```js
fact(slide, 'доход за год', 84.6, { type: 'xlsx', sheet: 'Итоги', cells: ['D20'], agg: 'value', scale: 1e6 }, { digits: 1 })
fact(slide, 'доля приложения', 72, { type: 'xlsx', sheet: 'Итоги', cells: ['D3','D4','D5'], agg: 'share_of', den: 'D20', scale: 0.01 })
fact(slide, 'рост IV/I кв.', 7, { type: 'xlsx', sheet: 'Помесячно', cells: ['M15','B15'], agg: 'ratio' })
fact(slide, 'пилотов', 12, { type: 'text', file: 'data/brief.md', quote: 'Запланировано 12 пилотов' })
fact(slide, 'срок релиза', 15, { type: 'user', date: '2026-10-26', quote: 'запуск в приложении с 15.12' })
```

Статусы из заливки ячеек (пилот или разработка) проверяются отдельно, по цвету: `openpyxl` → `ws[ref].fill.fgColor.rgb` сравнивается с цветом статуса из легенды модели.

## Нативные диаграммы PowerPoint (по выбору)

По умолчанию графики собираются фигурами (`barsTrend`, `slope` и другие): так держится редакционная графика, скобки роста и подписи в нужных местах. Если получатель будет править числа сам, нужна диаграмма PowerPoint с «Изменить данные»: компонент `nativeChart` (`kit/charts.js`).

```js
els.push(...K.nativeChart(body(), {
  type: 'col',                       // 'col' — столбцы, 'line' — линия, 'bar' — полосы
  label: 'премии', unit: 'млрд ₽', digits: 1,
  periods: ['2023', '2024', '2025'], // или cats: [...] для полос
  values: [15.0, 17.8, 19.6],        // или series: [{ name: 'Факт', values: [...] }, { name: 'План', values: [...] }]
  source: 'модель v3, лист «Итоги»', // строка происхождения в таблице; без неё описывается src
  // highlight: 'last' | 'max' | индекс | имя | false; labels: false; unitOnLabels: false; min, max — шкала
}, { src: { type: 'xlsx', sheet: 'Итоги', cells: ['D20', 'E20', 'F20'] } }));
```

- **В PPTX** — диаграмма PowerPoint со встроенной книгой `ppt/embeddings/*.xlsx`: на `Sheet1` категории в A, ряды в B…, значения с форматом числа и единицей (`#,##0.0" млрд ₽"`), ниже показатель, единицы, источник и пометка, что связи с моделью нет. Подписи значений и категорий берутся из данных и после правки в PowerPoint перестраиваются. Цвета (`C.accent`, `C.bar`, `C.axis`), шрифт `theme.json`, без сетки и оси значений.
- **В HTML-двойнике** — та же геометрия фигурами (элементы с `twin: 'chart'`): область построения задана вручную, шкала от `min` до `max`, ширина столбцов по `gapWidth`, как у PowerPoint. `render.sh` меряет подписи, PNG похожи на PPTX. В PPTX `build.js` двойник пропускает.
- **Факты**: каждое значение регистрируется через `num()` как «премии 2024» (один ряд) или «новые полисы: Факт I кв.» (несколько); подписи значений делают их читаемыми (`shown`). Пропуск (`null`) не рисуется и не регистрируется.
- **Режим фигур** того же компонента: `{ native: false }` в `opt`. Старые проекты без `nativeChart` собираются как раньше.
- **Проверка**: `pptx_audit.py` считает диаграмму инфографикой и даёт ERR, если нет встроенной книги, есть связь с внешним файлом, кэш диаграммы расходится с ячейками книги или шрифт не из темы.
- **Ограничения**: подписи ставит PowerPoint (`outEnd` у столбцов и полос, над точкой у линии), у пересекающихся линий они могут слипаться: тогда `labels: false` и `opt.show` или `slope`. Скобки роста, выноски и аннотации — только в режиме фигур. Двойник повторяет геометрию, а не растеризатор PowerPoint: открыть файл в PowerPoint всё равно нужно (раздел «Рендер и просмотр», п. 5). Quick Look и Keynote игнорируют часть оформления (формат подписей, цвета отдельных точек).

## Рендер и просмотр

1. `node build.js && ./render.sh`: проверь, что `font: true` и `overflow: []`.
2. Открой каждый `out/png/s*.png` через Read и посмотри сам. Проверка смотрит на боксы, но не на смысл: слипание подписей, пересечение связей и пустоты видны только глазами.
3. Для одного слайда: `ONLY=3 node build.js`, рядом пишется `out/check_s3.pptx`.
4. 4K-картинки: `SCALE=2 ./render.sh`, результат в `out/png@2x/` (3840×2160). PNG без сжатия.
5. Проверка в PowerPoint через Computer Use: `open -a "Microsoft PowerPoint" "<файл>.pptx"`, затем `request_access ["Microsoft PowerPoint"]`, затем скриншот окна. Закрыть: меню Файл → Закрыть, без сохранения.

## Тёмная и светлая версии

`THEME=light node build.js` даёт `<имя>_светлая.pptx` и `out-light/`. Если нужны обе с суффиксами, добавь `BOTH_THEMES=1`. Разметка одна. Если на светлом фоне что-то не читается (белые цифры на светло-красной ячейке), правь палитру, а не координаты.

## Частые поломки

| Симптом | Причина | Лечение |
|---------|---------|---------|
| в PowerPoint другой шрифт | имя в `theme.json` не совпадает с установленным | `system_profiler SPFontsDataType \| grep "Full Name: <шрифт>"` |
| текст вылез в PowerPoint, а в двойнике нет | PowerPoint чуть шире набирает кириллицу | запас 5–10% по ширине, `fit: 'none'` уже стоит |
| квадратик вместо символа | глифа нет в шрифте (× в Styrene) | заменить символ и записать в отчёт |
| фон размыт | фон 2560×1440 растянут на 4K | для 4K запусти `bg.py` с `W, H = 3840, 2160` |
| файл 10+ МБ | несжатые PNG-скриншоты | `sips -s format jpeg -s formatOptions 85` для фото и экранов |
